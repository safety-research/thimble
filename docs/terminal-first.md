# Terminal-first use

You can chat with thimble only in Claude Code and keep the browser as a dashboard.

- **Hide the chat.** *Hide the chat* in Settings removes the chat column. Alerts, permission requests, the orientation's progress and its Start move to a dock at the bottom left. A ⌘-click answers in its own box.
- **Terminal-first** (Settings, on by default). The orientation, its critic and the writers run as Claude Code background sessions, `thimble:orient · <workspace>`, `thimble:critic · <workspace>` and `thimble:writer · <workspace>`, each with its own folder, permission mode and tools. The orientation keeps every choice the Start card offers: the model, the effort (Ultracode included, with its workflows), fast mode, the permission mode, the critique, and the instructions you can edit.
- **At the bottom of your terminal.** ↓ at the prompt opens the agent tray, which lists the running threads, main's subagents and an entry for each background session. Pick one and press Enter to see it and type to it: what you type there reaches the thread or session, and the browser shows it with the answer. A background session's entry shows what a subagent's view would: a line for each tool call (`● Bash: git status`, `● add_card: Which tasks fail most?`) and each failed result (`✗ Read: …`), a line for each message to or from it (`✉ analyst (tray) → thimble:writer: …`, `✉ thimble:writer → main: …`), and its replies, a long one cut after 4,000 characters. Lines show within a few seconds, a batch at a time, and main's messages to the session go through the entry too. `claude attach <id>` shows the session itself, as Claude Code draws it. The statusline lists every running thimble agent with its state, dev and view builds included, on further lines when one line is full. A line after a start names the command that opens the session in another terminal (`claude attach <id>`), and a line after its run says it finished. `/thimble:agents` lists them all.
- **Names.** Every Claude Code session thimble starts is named `thimble:<role> · <workspace>`, since `claude agents`, the agent view and `/resume` list the sessions of every folder: main is `thimble:main · <workspace>` (also when `thimble -c` or `-r` resumes it, which replaces a `/rename`; your own `-n`/`--name` wins), and the background sessions are `thimble:orient`, `thimble:writer` (another document's writer is `thimble:writer-<doc>`), `thimble:critic`, `thimble:dev` and `thimble:view-<view>`, each followed by ` · <workspace>`. A session's tray entry is described by that name. A very long workspace name is shortened in it, with a short hash that keeps it apart from others. A background session an earlier thimble named without the workspace keeps that name until a new session replaces it. The statusline and a tray entry's lines leave the workspace out. A ⌘-click's thread runs under the thread's name, such as `fork(thread:probier-601)`.
- **Citations.** Main writes a citation in the terminal as a link on its number, which the browser shows as a chip.
- **Commands.** `/thimble:ask <thread> [message]` sends a message to a thread, as its composer in the browser would. With no message, it asks the thread's question again. `orient` and a view's build thread (`dev/<view>`) work as thread names too. `/thimble:orient [focus]` takes Start's switches as flags: `--no-deck`, `--no-views`, `--report` and `--no-critique`. It runs in the orientation's permission mode from Settings, with Terminal-first on or off.

## Caveats

- **Quitting main stops everything.** When your Claude Code session ends and no other session takes over as main, thimble stops every agent of the workspace: the orientation, writers, the critic, dev tickets and view builds. Background sessions are stopped with `claude stop`, which keeps their conversations for `claude attach`.
- **Esc stops an agent.** In the agent tray's view of a subagent or thread, Esc stops that agent, not just the view. To go back to main, press ↓ and pick main.
- **Don't press ← at main's prompt.** Claude Code moves your conversation into its background service, where thimble's tools are gone and the tray entries stop. To get back, quit, stop the copy with `claude stop <id>` (`claude agents` lists it under your conversation's name) and run `thimble --continue`.
- **Messages to a session are not your approval.** What you type in a tray entry, and what you send a background session from the browser, reaches it as a message from another session, so it does not count as your approval. Answer its permission prompts in the browser or with `claude attach`.
- **Delays.** A message typed in a tray entry reaches its session within about ten seconds. A follow-up to a finished thread shows Claude Code's own line `Resuming agent <id>`.
- **Trust and the statusline.** `claude --bg` starts only in a folder Claude Code trusts. The install asks once whether to mark thimble's workspaces folder trusted in Claude Code's config (`install.sh --trust-workspaces` or `--no-trust-workspaces` answers without asking), and `thimble uninstall` takes the entry back. `thimble` passes its statusline to your session at launch with `--settings`, merged into your own `--settings` and running your own statusline (from `--settings` or your user settings, at its refresh interval) before it; it writes no settings file. A statusline in the folder's own `.claude/` settings does not show, since `--settings` outranks it.
- **Turn endings and long calls.** `thimble` sets `CLAUDE_CODE_TERMINAL_MCP_TOOLS` to Agent, SendMessage and the thimble tools whose result the browser shows, so that a turn ending on one of them needs no closing words. Where the installed Claude Code does not read the variable, main ends such turns with a marker the browser hides. `thimble doctor` shows which applies, on its *turn endings* line. Background sessions run with `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS=0`, so that a long thimble call such as the critique stays a foreground call rather than one Claude Code moves to the background after two minutes.
