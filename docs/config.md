# thimble's config

thimble's agents take their settings from `~/.thimble/config.json` (`$THIMBLE_HOME/config.json` when THIMBLE_HOME is set). With no file, every agent runs on the defaults below. A workspace can override any key but `browser`, `cardWait` and `extensions` in `workspaces/<workspace>/config.json`. Objects merge key by key, and `null` means thimble's default.

The Settings pane writes this file for the models and efforts, the fast mode of the classifiers and the code tickets, and the code tickets' permission mode. Each change goes to the file the value came from, so a key the workspace's file sets is changed there. Edit the file by hand for everything else. A change applies to the next start of an agent, with no restart of Claude Code.

When your Claude Code session or one of thimble's agents edits this file or a workspace's `config.json`, it asks you first, in every permission mode, Bypass and Auto included, like an edit of the corpus with `data` at `"ask"`. Your session's request shows on the permission card in the browser and in the terminal, and an agent's request in the terminal; both say that thimble asks because the edit changes thimble's config. A session that has nobody to ask, such as an extension's program run without a chat or `thimble fix`, can't edit these files.

thimble changes none of Claude Code's settings files. The orientation, its critic, the writers, view builds, view reviews and report checks are subagents of the Claude Code session you start with `thimble`: they run in that session's permission mode and in the fence thimble adds to your own settings for it. Only code tickets keep a permission mode and a fence of their own (the `dev` entry).

```json
{
  "sandbox": { "use": "when-available", "enforce": true },
  "browser": "system",
  "agents": {
    "orientation": { "model": "claude-opus-5-5", "effort": "xhigh", "data": "ask" },
    "writer": { "web": "off" },
    "dev": { "web": "off" }
  }
}
```

If the file isn't valid JSON, or a key or value is unknown, no agent starts. The Settings pane and `thimble doctor` show the error, which names the file and the key. `thimble doctor` also prints which file is read and which browser is used.

## Top-level keys

| Key | Values | Default | What it does, and the risk |
|---|---|---|---|
| `installs` | `"ask"`, `"deny"`, `"allow"` | read and ignored | Earlier versions sent each command that installs software to you. Such commands now follow your Claude Code session's permission mode, as every other command does: thimble adds no rule for them. |
| `sandbox.use` | `"when-available"`, `"never"` | `"when-available"` | Runs the Bash of your Claude Code session, and so of thimble's agents, in Claude Code's sandbox where it can run (Linux needs bubblewrap and socat; `thimble doctor` says what is missing). In the sandbox, Bash can write only thimble's work folders in the workspace and Claude Code's temp folder, can't write the corpus or thimble's config, and has the network the orientation's `network` gives. A code ticket runs in a fence of its own, and its Bash can also commit to the ticket's branch. The ticket's checks, and the copy of thimble the server screenshots before and after the change, run in thimble's sandbox runtime (Anthropic's sandbox runtime, installed with thimble; it needs Node 20.11 or later, and on Linux bubblewrap, socat and ripgrep): no network, no view of your home folder, and writes only to the ticket's worktree and its cache. The edited code first runs outside a sandbox once merged into your install, so just before that thimble asks "Apply this change to thimble's own code?", in every permission mode, Bypass and Auto included, and merges only on your Allow, and only the change it named; otherwise the change stays on its branch. `thimble fix` asks the same in the terminal. Where the sandbox runtime can't run (`thimble doctor` says why), a ticket's checks run outside the sandbox, so thimble also asks before the ticket starts. `"never"` turns the sandbox off, so Bash runs with your user's full access, limited only by the permission mode, and the launcher says so. |
| `sandbox.enforce` | `true`, `false` | `true` | `true` refuses to start a code ticket whose Bash would run outside the sandbox, and says why. On Linux, run the installer again with `--sandbox-deps` to install what the sandbox needs. With `false`, code tickets run without the sandbox where it can't run. Your own Claude Code session starts either way; where the sandbox can't run, it starts without thimble's fence, and the launcher warns about it. |
| `browser` | `"system"`, `"bundled"`, `"off"` | the system browser when one is found, else Playwright's Chromium if installed, else off | The browser for screenshots: card checks, view checks and reviews, and the screenshot tool. `"system"` uses Chrome, Edge or Chromium installed on the machine. `"bundled"` uses the Chromium that the installer downloaded. `"off"` takes no screenshots, so cards and views are checked without pictures and graphics aren't repaired. Only in the file in thimble's home. Run `thimble restart` after changing it. |
| `cardWait` | minutes, a number above 0 and up to 720 | `10` | How long a code ticket's permission card waits for your answer. A request nobody answers in that time is declined, and the card says so, with the wait. It applies to code tickets' requests, and to the card that asks before a change reaches thimble's own code. Requests of your session and of thimble's agents are never declined on a timer. A change applies to the next card. Only in the file in thimble's home. |
| `extensions.<name>.enabled` | `true`, `false` | `true` | `false` switches the extension off in every workspace. `thimble extension off <name>` writes it and `thimble extension on <name>` takes it out. Settings → Extensions switches one off for a single workspace. Only in the file in thimble's home. |

## Agents

`agents` has one entry per agent:

- **`orientation`**: the orientation. Its `data`, `web` and `network` also set the fence of your Claude Code session, which every one of thimble's agents shares, and its `subagentModel` and `subagentEffort` set `thimble:helper`, the type the orientation starts its own subagents as
- **`critic`**: the critique of the orientation, which runs only when Start's Critique and revise switch (off by default) or `/thimble:orient --critique` turns it on
- **`writer`**: the report writers
- **`checks`**: the report checks
- **`dev`**: view builds, view reviews and code tickets
- **`labels`**: the label classifier, and the call that checks whether an extension's view fits a corpus
- **`cardCheck`**: the card check's reading of a card's picture
- **`suggest`**: the call that proposes a viewer for a file type
- **`refusal`**: the model and effort a classifier's call runs again on when its own model refuses it

Each agent runs on exactly the model and effort its entry gives, the defaults included, unless Start, `/thimble:orient` or a start tool names another model or effort for one run. None of them takes your own Claude Code model or effort. The launcher unsets `CLAUDE_CODE_EFFORT_LEVEL` (passing it on as your session's own effort), `CLAUDE_CODE_SUBAGENT_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` in the session it starts, and blanks them there where an `env` block of your Claude Code settings sets them, which your session's effort then follows too. thimble's single model calls run without them, so that none can change what runs. Your organization's managed settings rank above thimble's, so a variable an `env` block there sets still applies.

`labels`, `cardCheck` and `suggest` are single model calls with no tools, so they take only `model`, `effort`, `fast` and `prompt`. Each runs at exactly the model, effort and fast mode Settings shows for its row (`labels`: Opus 5.5 at low effort, fast mode off; `cardCheck`: Opus 5.5 at high effort, fast mode on; `suggest`: Opus 5.5 at low effort). When a call's model refuses it, it runs once more on the `refusal` row's `model` and `effort` (Opus 4.8 at high effort), or not again when that row is off. When an extension's program runs one of their tasks ([agents.md](agents.md)), they also take `network`, `data` and `env` for that program. It has no thread to ask you in, so with `data` at `"ask"` it can't edit the corpus. Set `data` to `"allow"` to let it.

An extension's agent has the entry `"<extension>:<agent>"`, such as `"swarm-orient:swarm-reader"`. It runs as a subagent of the orientation, in your session's sandbox and permission mode, so it takes only `model`, `effort`, `web`, `network` and `prompt`. Its `model` and `effort` default to those its extension's `agent.json` gives it, else the orientation's subagents', its `web` defaults to `"off"` and its `network` to `"on"`. They can only take away what the orientation's allow. With `web` off it has no web tools. With `network` off while the orientation's is on, it has no Bash, since all agents in a session share one sandbox network. Its `prompt` replaces the extension's prompt file for it. Settings has a row for each agent of the extensions running in the workspace, where its `model` and `effort` can be changed. An extension's `agents/orientation/agent.json` prompt is not an agent: it adds to the orientation's instructions, or replaces them, and the orientation keeps its own settings (`agents.orientation`).

| Key | Values | Default | What it does, and the risk |
|---|---|---|---|
| `model` | a model id, such as `"claude-opus-5-5"` | per agent: the orientation uses your own Claude Code `model`, else Opus 5.5 | The agent's model. |
| `effort` | `"low"`, `"medium"`, `"high"`, `"xhigh"`, `"max"` | per agent: `"xhigh"` for the orientation | Higher efforts use more tokens. A stored `"ultracode"` reads as `"xhigh"`. A model without effort levels, such as Haiku, runs with none. |
| `fast` | `true`, `false` | per agent: on for `cardCheck` and `dev` | Fast mode, on models that have it, for `labels`, `cardCheck` and `suggest`, and `dev`'s for code tickets, which stay jobs of thimble's server. A view build or review runs without it. Read and ignored for the other agents, which run without a fast mode of their own. |
| `permissionMode` | `"manual"`, `"auto"`, `"bypass"` | `null`: your Claude Code session's mode | Only for `dev`: the permission mode of code tickets. Manual asks you about each call that isn't already allowed. Auto lets Claude Code's classifier decide. Bypass allows every call that would otherwise ask you, except the ones `network` sends to you. The code tickets' row in Settings edits this key. Read and ignored for every other agent, since thimble's agents run in your Claude Code session's mode. |
| `web` | `"ask"`, `"off"`, `"allow"` | `"ask"`; `"off"` for `dev` | WebFetch and WebSearch. The orientation's sets them for your session and every agent: `"ask"` follows the permission mode, so in Manual each fetch or search goes to you, except for sites you allowed for the workspace; `"off"` removes both tools; `"allow"` runs them unasked in every mode, so an agent can send text from your corpus to any website. For any other agent only `"off"` counts, which keeps that agent off WebFetch and WebSearch; for `dev` it also sets code tickets' web. |
| `network` | `"off"`, `"on"` | `"on"` | Network access for Bash. The orientation's sets it for your session and every agent, view builds included: with `"off"`, Bash has no network where the sandbox runs. `dev`'s sets it for code tickets, whose commands go to you first in every mode where the sandbox doesn't run. Each agent's own, the orientation's included, sets it for an extension's program that runs the agent or one of its tasks, `"on"` where the agent sets none. thimble's own critic, writers and checks don't read theirs, since they run in your session's fence. `"on"` lets Bash reach the network, as far as your own Claude Code sandbox settings allow. |
| `sandbox` | `"on"`, `"off"` | `"on"` | Only for `dev`, and for an extension's program that runs an agent: `"off"` runs a code ticket's Bash, or the program, outside the sandbox, so it can write anywhere you can, and `sandbox.enforce` then doesn't stop it. thimble's own orientation, critic, writers and checks don't read it, since they run in your session's sandbox. |
| `data` | `"ask"`, `"allow"`, `"off"` | `"ask"` | Edits of files in the corpus. The orientation's sets them for your session and every agent: `"ask"` sends each one to you in every permission mode, Bypass and Auto included; `"allow"` leaves them to the permission mode; `"off"` refuses them. Bash can't write the corpus either way. `dev`'s sets them for code tickets. Each agent's own, the orientation's included, sets them for an extension's program that runs the agent or one of its tasks, `"ask"` where the agent sets none. thimble's own critic, writers and checks don't read theirs, since they run in your session's fence. |
| `env` | a list of environment variable names, such as `["OPENAI_API_KEY"]` | `[]` | Variables of thimble's server that an extension's program running this agent or one of its tasks gets, such as the API key of a harness that brings its own model. A program gets no other variable of yours. thimble's own agents don't read it. |
| `memory` | `"inherit"`, `"on"`, `"off"` | `"inherit"` | Whether the agent reads CLAUDE.md files. `"off"` leaves them out of its context; `"on"` and `"inherit"` give it the CLAUDE.md files your session reads. |
| `prompt` | a file path, or `null` | `null` | Replaces the agent's prompt file from thimble's `prompts/` folder (`orient.md`, `critic.md`, `writer.md`, `check.md`, `dev.md`, `labels.md`, `card-check.md`). Copy the original and edit it. It is filled in the same way, and relative paths are resolved from the config file's folder. A replacement prompt can drop the rules that keep an agent within its task. |
| `auto` | `true`, `false`, `null` | `null`: on | Only for `cardCheck`: whether the card check reads each new card by itself. With `false`, a card is checked only when you click Check the card or Check again in its details. A card shows the check only for a real problem it found, as a red ✕ at its takeaway; a fix is applied in place, with Undo in the card's details. |
| `subagentModel` | a model id, or `null` | `null`: the orientation's model | Only for `orientation`: the model of `thimble:helper`, the type the orientation starts its own subagents as. A subagent it starts as another type, such as general-purpose or Explore, runs on the orientation's own model and effort. |
| `subagentEffort` | `"low"`, `"medium"`, `"high"`, `"xhigh"`, `"max"`, or `null` | `null`: the orientation's effort | Only for `orientation`: the effort of `thimble:helper`. |

## What stays as it is

- Your own Claude Code session keeps its permission mode and your settings. thimble adds its fence to them for the session it starts, and its agents run inside that fence.
- Neither your session nor any agent thimble starts can read `server.json` in thimble's home, which holds the token of thimble's local API, or `session.key` beside it, which proves which of thimble's sessions a call comes from: the fence denies both files to Read and Bash, and the sandbox hides them. An extension's program that runs an agent gets a token of its own instead, valid only for that agent's tools and only while it runs ([agents.md](agents.md)).
- Card code, an extension's code among it, runs in the notebook kernel as your user, with your network, whatever `network` and `sandbox` say.
- The kernel runs in Anthropic's [sandbox runtime](https://github.com/anthropics/sandbox-runtime), which thimble installs (it uses Seatbelt on macOS and bubblewrap on Linux). The kernel reads the corpus, the workspace and the system, and writes only in the workspace, apart from its views, the card types and extensions thimble found there, which your session's and the orientation's prompts are made from, and the `trusted` folder, which holds the files thimble's hooks trust (`subagents.json`, `callers.jsonl`, `launch.json`). It can't read your home folder, thimble's config, other workspaces or your Claude Code login. It keeps the network, so it can also reach local services, thimble's own API among them. Without Node, the kernel runs in bubblewrap directly on Linux, with the same limits, and unsandboxed on macOS; `thimble doctor` says which. `"kernel_wrap"` in the workspace's `settings.json` picks one: `"srt"`, `"bwrap"` or `"none"` (no sandbox). A workspace set to a sandbox that can't run gets no kernel.
- `thimble fix` runs only in a development install (a git clone of thimble), while the server is down, and only in a terminal: it asks you there before its change is applied, and before it starts too where the sandbox runtime can't run. While it works nobody can be asked, so it runs its Bash unasked, in the sandbox where it can run.
- Earlier versions kept the agents' models and permission modes in each workspace's `settings.json`. These settings are moved to that workspace's `config.json` the first time it is read, so each workspace keeps running as before. The old *View builds* permission row is now the dev agent's row. If the two rows were different, the stricter one is kept.
- Earlier versions of this file also gave each agent a permission mode and `fast`, and set `installs`. Those this page marks as read and ignored load without an error, `thimble doctor` lists them, and saving Settings drops them. Each agent's `network`, `data`, `sandbox` and `env` stay, since an extension's program that runs the agent reads them.
