Draw an interactive card, or a new version of a card you drew. The card shows where this call stands in the conversation, above the words you write after the call, so when you write about it, name it by its title.

1) Data: write the rows as a JSON file, in this folder or in the temp folder `$TMPDIR` ({{TMPDIR}}), with code that reads the records (Python, jq, ...), and give its path as `data`; a path may start with `$TMPDIR/`. The file holds a list of rows (JSON records), an object with a "rows" list, or JSON Lines. thimble keeps a copy of the rows for the card. The call tells you how many rows the card read, their columns and the first row, so you do not have to print the rows to check the file.

2) `view` is JavaScript that defines `function view(props, surface)`. It runs in a sandbox with no files, no network and no timers (no import, export, require, `$`, globalThis or process, and no call of eval or Function). It returns a drawing made with `const { Box, Text, Button } = surface.elements`, each called as a function with Ink props and `children`: Box (flexDirection, which is "row" when you do not give it, flexGrow, flexShrink, flexWrap, gap, width and height in cells or as "50%", padding*, margin*, borderStyle "round"|"single", borderColor, justifyContent, alignItems), Text (color and backgroundColor as "#rrggbb", bold, dimColor, underline, inverse, wrap: "truncate-end"; nest Texts for runs of color in one line), Button (onPress, plain: true for a bare clickable label, children: strings or Text). Any characters draw: █ ▀ ▄ half-blocks, ⣿ braille dots, box lines. `props.rows` is all the rows, `props.title` the title, `props.query` the live search text or null, and `surface.columns` the card's width in cells. Draw what fits on a screen or two: a drawing of thousands of elements does not draw, so show a page of rows and let keys move through them.

3) State: `surface.state` (undefined at first) and `surface.setState(next)` (the whole state, plain JSON). thimble keeps the analyst's state when the card draws again, also in a resumed session. Compute everything (filter, sort, search, statistics) in view on each call.

4) Input: `const keys = "sn/"` lists the keys the card takes while the prompt box is empty (letters, digits or signs, but not v, which thimble keeps for itself); `function onKey(key, surface, props)` gets each one and calls surface.setState. `/` also starts a live search the analyst types in the prompt box: props.query changes at each keystroke, Enter keeps it, and an empty box ends it. A click on a Button runs its onPress. `surface.onPointer(fn)` (call it in view each time) gets each click on the card as {type: "down"} and then {type: "up"}, with x and y in cells from the card's top left corner.

5) The call draws the card and returns what it read and a text copy of what it draws, or the view's error. `actions` (optional) tries keys and clicks in order, each {"key": "s"}, {"click": "words on a Button"} or {"click": [x, y]} (cells, as onPointer gets them), and returns the text copy after each one; then the card goes back to its first state. To change a card, call card again with its `id`: the new version takes the place of the old one, and no second card is drawn. Without `id`, the call draws a new card.
