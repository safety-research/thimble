Draw an interactive card, or a new version of one. The card stands where this call stands, above the words you write after it, so name it by its title.

1) Data: with code that reads the records, write the rows as a JSON file in this folder or in `$TMPDIR` ({{TMPDIR}}), and give its path as `data`: a list of rows, JSON Lines, or one object. The call says what the card read.

2) `view` is plain JavaScript (no JSX) that defines `function view(props, surface)`, in a sandbox (no files, network, timers or modules). It returns calls of `const { Box, Text, Button } = surface.elements` with Ink props and `children`, such as `Text({ bold: true, children: "late" })`: Box (Ink's flex props, flexDirection "row" by default, sizes in cells or "50%", borderStyle "round"|"single", borderColor), Text (color and backgroundColor "#rrggbb", bold, dimColor, underline, inverse, wrap: "truncate-end"; nest Texts for runs of color), Button (onPress, plain: true; children: strings and Text, or Boxes: a Button around rows takes a click anywhere on them). `props.rows` is the rows (an object's "rows" list), `props.data` the whole object, `surface.columns` the card's width now, which changes when a side pane opens: lay out every column from it. Thousands of elements do not draw: draw a dense grid as runs of text. Code outside view runs once per version: build indexes there (`let byDay; … byDay ??= index(props.rows)`).

3) The card answers the analyst's question by itself: each part of the question has its answer on the card, in words that code computes from the rows, next to the marks that show it, and its first line states the answer, since the analyst reads it first. Pick the form the question asks for, such as small multiples for how a value changes, or a matrix for how groups overlap; thimble draws the title above it. Text with no color reads on light and dark backgrounds; a color must read on both. Show what a color or a mark means with a sample (`█ survived`); mark the selected item with bold or `▸`. Size each column from its longest value; a cut value keeps the part that tells it apart, and a line says how many items it leaves out (`+47 more`). Two numbers that touch read as one, and a cell that holds two records shows how many it holds. Put each axis label at its tick (an end label that does not fit ends at its tick) and keep one scale across states. Keep to about 30 rows, details beside or under the selected item; when rows do not fit, show a page and say which ("rows 1-14 of 28").

4) State: `surface.state` (undefined at first) and `surface.setState(next)` (plain JSON), kept across drawings and resumes. Compute filters, sorts and statistics in view. Keep the selected record by its key, not its place.

5) Input: `const keys = "jk"` lists the letters the card takes at an empty prompt; `function onKey(key, surface, props)` gets each. Only letters reach a card (a digit or a sign types into the prompt), and {{KEPT}} open thimble's designer, fixes and panes: j and k suit next and previous. Give the card the keys or Buttons that the analyst's next question needs, such as the records behind a count or the next page. `surface.onPointer(fn)` (in view) gets clicks as {type: "down"|"up", x, y} in cells from the card's top left, for where the place is the point (a grid's cell).

6) The call returns a text copy of the card at its width, or the view's error. `actions` tries keys and clicks ({"key": "s"}, {"click": "words on a Button"}, {"click": [x, y]}) and returns a copy after each; then the card goes back as it was. Try each way in, and read each copy as the analyst will: fix what they would misread or could not read, such as labels that run together or a cut value, in one new version before you reply. To change a card, also when the analyst asks, call card with its `id`; for a small change give `edits` (each {old, new}, as the Edit tool takes them) in place of `view` and `data`, as the whole view takes half a minute. A new question gets a new card.
