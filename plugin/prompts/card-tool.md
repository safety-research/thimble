Draw an interactive card, or a new version of a card you drew. The card stands where this call stands, above the words you write after it, so name it by its title.

1) Data: with code that reads the records, write the rows as a JSON file in this folder or in `$TMPDIR` ({{TMPDIR}}), and give its path as `data`: a list of rows, JSON Lines, or one object. The call says how many rows the card read, their columns and the first row.

2) `view` is plain JavaScript (no JSX) that defines `function view(props, surface)`, in a sandbox (no files, network, timers, modules or eval). It returns calls of `const { Box, Text, Button } = surface.elements` with Ink props and `children`, such as `Text({ color: "#c0504d", bold: true, children: "late" })`: Box (flexDirection, "row" by default, flexGrow, flexShrink, flexWrap, gap, columnGap, width and height in cells or "50%", padding*, margin*, borderStyle "round"|"single", borderColor, justifyContent, alignItems), Text (color and backgroundColor "#rrggbb", bold, dimColor, underline, inverse, wrap: "truncate-end"; nest Texts for runs of color), Button (onPress, plain: true, children: strings or Text only). `props.rows` is the rows (an object's "rows" list), `props.data` the whole file when it is an object, `surface.columns` the card's width now, which changes when a side pane opens: lay out every column from it. Thousands of elements do not draw: draw a dense grid as runs of text. Code outside view runs once per version, so keep what does not change there, such as an index of the rows (`let byDay; … byDay ??= index(props.rows)`).

3) The card answers the analyst's question by itself: each part of the question has its answer on the card, in words that code computes from the rows, next to the marks that show it. Pick the form the question asks for, such as lines or small multiples for how one value changes with another, or a matrix for how groups overlap. thimble draws the title above it. The background may be light or dark: text with no color reads on both, and a color must be clear on white and on black. Show what a color or a mark means with a sample (`█ survived`), and keep that meaning: mark the selected item with bold, an underline or `▸`. Show each value whole or end it with `…`, and say how many items a line leaves out (`+47 more`). Put each axis label at its tick (an end label that does not fit ends at its tick) and keep one scale across states. Keep to about 30 rows, with details beside or right under the selected item; when the rows do not fit, show a page and say which ("rows 1-14 of 28").

4) State: `surface.state` (undefined at first) and `surface.setState(next)` (plain JSON), kept when the card draws again, also in a resumed session. Compute filters, sorts and statistics in view, from the rows in the state's filter. Keep the selected record by its key, not by its place.

5) Input: `const keys = "sn"` lists the letters the card takes at an empty prompt (not {{KEPT}}: they open thimble's designer, fixes and panes); `function onKey(key, surface, props)` gets each. Give the card the keys or Buttons that the analyst's next question needs. A click on a Button runs its onPress; a Button around a whole row takes a click anywhere on it. `surface.onPointer(fn)` (call it in view) gets each click as {type: "down"|"up", x, y}, in cells from the card's top left; use it only where the place is the point, such as a cell of a grid.

6) The call returns a text copy of the card at its width, or the view's error. `actions` tries keys and clicks ({"key": "s"}, {"click": "words on a Button"}, {"click": [x, y]}) and returns a copy after each; then the card goes back as it was. Try each way in. Read each copy as the analyst will. Fix what they would misread or could not read, such as labels that run together, a cut value or a wrapped line, in one new version before you reply. To fix or change a card, also when the analyst asks, call card with its `id`. A new question gets a new card.
