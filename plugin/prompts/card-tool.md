Draw an interactive card, or a new version of a card you drew. The card stands where this call stands, above the words you write after it, so name it by its title. A new version stands at its own call, and the earlier call shows a line that points to it.

1) Data: with code that reads the records, write the rows as a JSON file in this folder or in `$TMPDIR` ({{TMPDIR}}), and give its path as `data`: a list of rows, an object with a "rows" list, or JSON Lines. The call says how many rows the card read, their columns and the first row.

2) `view` is plain JavaScript (no JSX) that defines `function view(props, surface)`, in a sandbox (no files, network, timers, modules or eval). It returns calls of `const { Box, Text, Button } = surface.elements` with Ink props and `children`, such as `Text({ color: "#c0504d", bold: true, children: "late" })`: Box (flexDirection, "row" by default, flexGrow, flexShrink, flexWrap, gap, columnGap, width and height in cells or "50%", padding*, margin*, borderStyle "round"|"single", borderColor, justifyContent, alignItems), Text (color and backgroundColor "#rrggbb", bold, dimColor, underline, inverse, wrap: "truncate-end"; nest Texts for runs of color), Button (onPress, plain: true, children: strings or Text only). `props.rows` is the rows, `props.data` the whole file when it is an object, `surface.columns` the card's width now. Thousands of elements do not draw: draw a dense grid as runs of text. Code outside view runs once per version, so keep what does not change there, such as an index of the rows (`let byDay; … byDay ??= index(props.rows)`).

3) thimble draws the title above it. The background may be light or dark: text with no color reads on both, and a color must be clear on white and on black. Show what a color or a mark means with a sample (`█ survived`), and keep that meaning: mark the selected item with bold, an underline or `▸`. Lay out from `surface.columns`, which changes when a side pane opens. Show each value whole or end it with `…`, and say how many items a line leaves out (`+47 more`). Put each axis label at its tick (an end label that does not fit ends at its tick) and keep one scale across states. Keep to about 30 rows, with details beside or right under the selected item; when the rows do not fit, show a page and say which ("rows 1-14 of 28"). State the finding in words that code computes from the rows, next to what it counts.

4) State: `surface.state` (undefined at first) and `surface.setState(next)` (plain JSON), kept when the card draws again, also in a resumed session. Compute filters, sorts and statistics in view, from the rows in the state's filter. Keep the selected record by its key, not by its place.

5) Input: `const keys = "sn"` lists the letters the card takes at an empty prompt (not {{KEPT}}, which are thimble's); `function onKey(key, surface, props)` gets each. Give the card the keys or Buttons that the analyst's next question needs. A click on a Button runs its onPress. `surface.onPointer(fn)` (call it in view) gets each click as {type: "down"|"up", x, y}, in cells from the card's top left; use it only where the place is the point, such as a cell of a grid.

6) The call returns a text copy of the card at its width and, when it differs, beside a side pane; or the view's error. `actions` tries keys and clicks ({"key": "s"}, {"click": "words on a Button"}, {"click": [x, y]}) and returns a copy after each; then the card goes back as it was. Try each way in. Read each copy as the analyst will. Fix what they would misread or could not read, such as labels that run together, a cut value or a wrapped line, in one new version before you reply. To fix or change a card, also when the analyst asks, call card with its `id`. A new question gets a new card.
