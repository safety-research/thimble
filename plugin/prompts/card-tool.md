Draw an interactive card, or a new version of a card you drew. The card stands where this call stands, above the words you write after it, so name it by its title. A new version stands at its own call, and the earlier call shows a line that points to it.

1) Data: with code that reads the records, write the rows as a JSON file in this folder or in `$TMPDIR` ({{TMPDIR}}), and give its path as `data` (it may start with `$TMPDIR/`): a list of rows, an object with a "rows" list, or JSON Lines. The call says how many rows the card read, their columns and the first row, so you need not print them.

2) `view` is JavaScript that defines `function view(props, surface)`, in a sandbox (no files, network, timers, import, require, `$`, globalThis, process, eval or Function). It returns elements of `const { Box, Text, Button } = surface.elements`, called with Ink props and `children`: Box (flexDirection, "row" by default, flexGrow, flexShrink, flexWrap, gap, columnGap, width and height in cells or "50%", padding*, margin*, borderStyle "round"|"single", borderColor, justifyContent, alignItems), Text (color and backgroundColor "#rrggbb", bold, dimColor, underline, inverse, wrap: "truncate-end"; nest Texts for runs of color), Button (onPress, plain: true, children: strings or Text only). `gap` also spaces the lines of a Box that wraps; `columnGap` does not. `props.rows` is the rows, `props.data` the whole file when it is an object, `props.title`, `props.query` the live search or null, and `surface.columns` the card's width now. Thousands of elements do not draw.

3) thimble draws the title above it, so the view does not repeat it. The background may be light or dark: text with no color reads on both, and a color must be clear on white and on black. Show what a color or a shade means with a sample (`█ survived`), and keep that meaning: mark the selected item with bold, an underline or `▸`, not with a shade. Lay out from `surface.columns`, which changes when a side pane opens. Show each value whole or end it with `…`, and say how many items a line leaves out (`+47 more`). Keep to about 30 rows; when the rows do not fit, put the rows that answer the question in the first view and say which part shows ("rows 1-14 of 28"). Draw a field only for the records that have it, and give each record a mark of its own.

4) State: `surface.state` (undefined at first) and `surface.setState(next)` (plain JSON), kept when the card draws again, also in a resumed session. Compute filters, sorts and statistics in view. Keep the selected record by its key, not by its place.

5) Input: `const keys = "sn/"` lists the keys the card takes at an empty prompt (not {{KEPT}}, which are thimble's); `function onKey(key, surface, props)` gets each. thimble lists the keys under the card. With `/` in keys, the analyst types a live search in the prompt box (props.query); Enter keeps it, an empty box ends it. A click on a Button runs its onPress, so make each thing to click a Button. `surface.onPointer(fn)` (call it in view) gets each click as {type: "down"|"up", x, y}, in cells from the card's top left; use it only where the place is the point, such as a cell of a grid.

6) The call returns what the card read and a text copy of it, at its width and, when it differs, at the narrower width beside a side pane; or the view's error. `actions` tries keys, clicks and searches ({"key": "s"}, {"click": "words on a Button"}, {"click": [x, y]}, {"search": "words"}) and returns a copy after each; then the card goes back as it was. Try each way in. Read each copy as the analyst will: labels that run together, ticks that miss their marks, a legend that wraps, a cut value, a missing row. Fix what you find in a new version before you reply, so the analyst never reads about a defect they can see; stop when the copies show nothing to fix. To fix or change a card, also when the analyst asks, call card with its `id`: the new version replaces the old one. A new question gets a new card.
