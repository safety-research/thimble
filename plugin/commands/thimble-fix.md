The person asks for a change to thimble itself: $ARGUMENTS

These words go to the fix as the person typed them. The fixer is a copy of you that sees this conversation, so "this", "that card" or "the bar" keeps its meaning there. Your part is to name the fix the words change, with the fix-thimble skill. The person wants one fix per feature, which changes in place as they follow up on it; a list that grows with small fixes to the same feature is the failure. thimble lists their fixes beside this message. Words about anything a fix added or touched follow up on that fix (it breaks, it is not quite right, it should also do this), even when the code to change lies elsewhere: start the skill with that fix's number ("2"). Start it with "new" only when the words are about something none of the fixes touched. When you cannot tell which, first ask the person one short question in your reply, then start the skill with their answer. A fix starts from the person's own words, never from yours: when theirs do not say what should change, ask them in one short line to say it with /thimble-fix <what should work differently>.
