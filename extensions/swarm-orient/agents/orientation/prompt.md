This corpus is a swarm: many accounts acting on shared pages or channels. Every record must be read by a model before you draft, not sampled.

1. List the records and write the shares. The Swarm reader prints the records place by place in time order, a save as the lines it changed. From your work folder, run `python ../../extensions/multiagent-swimlane/cards/multiagent-swimlane/reader.py --in <corpus folder> --shares shares` with `--files '<glob>'` for each of {{files}}: it begins with each file and the records it reads there, or why it reads none, and its last line says how many records it read, from which files, and the N shares it wrote to `shares/share-1.txt` to `share-N.txt`, each as much as one agent reads whole. When it counts no record, this corpus is no swarm: leave the rest of these steps.
2. Label every record with a prompt label that fits the analyst's request. When they asked for something, its values are what the request needs to tell records apart, such as asks for help, offers help and neither for "Did the agents ask each other for help?". When they asked for nothing in particular, read a few shares and draft values for what the accounts do there. A model judges each record alone, so choose values that one record can show. Try the label on 200 records, then apply it with comments over every record of the files the Swarm reader reads records in. Apply it again unchanged until no record is left unlabeled.
3. Read every record in order. Give each share to a `swarm-reader` agent with its file's full path and the analyst's request as they wrote it, if they made one, as many at once as you can, until all N have reported. Give a share whose reader failed, or read fewer records than its file's last line counts, to a new reader.
4. Before you draft, check the counts: in the files the reader reads, the records the label marked must equal the records its listing counts there with those it left out or found repeated, and the records the readers read, added up, must equal the records it counts. Then put the counts in the deck as a card whose output lists them: for each file, the records the listing counts, the records the label marked and the records the readers reported reading, then each file the reader read none of, with the reason its listing gives. Its takeaway cites that output, so the analyst can see that every record was read.
5. Show the coordination with `multiagent-swimlane` cards, choosing first the episodes the readers reported that answer the analyst's request: for each, its significant actions with your summaries, each account's goal and the links between the actions.
